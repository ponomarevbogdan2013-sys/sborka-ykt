- серверный (nginx, не в git — правка в `/etc/nginx/sites-available/sborka`, бэкапы в `backups/`) · баг «сайт вообще не открывается на мобильном интернете» (404, разные браузеры — Safari и Yandex): резервный HTTP→HTTPS редирект на порту 80 (шаблон certbot) сверял заголовок `Host` побуквенно с punycode-строкой и при несовпадении отдавал голый 404 вместо редиректа; на части мобильных сетей `Host` приходит не в этом виде (прокси операторов и т.п.) — воспроизвёл вручную (кириллический `Host`, случайный мусорный `Host` → 404 вместо 301). Заменил на безусловный редирект `location / { return 301 https://xn--14-6kcay4b4agj.xn--p1ai$request_uri; }` — сервер целиком отдан под sborka, сверять Host не для чего. Попутно нашёл и поправил вторую ошибку: `return` прямо в `server{}` (не в `location`) выполняется до выбора location и перебивает даже `/.well-known/acme-challenge/` — из-за этого при первой попытке фикса acme-challenge тоже начал редиректить; вынес `return` в `location /`, `/.well-known/acme-challenge/` проверен отдельно (отдаёт файл, не редиректит) — `certbot renew --dry-run` подтвердил: «all simulated renewals succeeded», обновление сертификата не сломано.
- серверный · баг «сайт виснет на середине загрузки на телефоне» (владелец воспроизвёл даже в приватной вкладке — не кэш): во всех трёх html (`index.html`, `m.html`, `p.html`) шрифт Google Fonts был подключён обычным блокирующим `<link rel="stylesheet">` — пока `fonts.googleapis.com`/`fonts.gstatic.com` не ответит, браузер не показывает страницу целиком. У мобильных операторов в РФ эти домены нередко недоступны/тормозят — отсюда зависание именно на мобильном интернете. Переведено на неблокирующую загрузку (`rel=preload` + `media=print` → `onload=this.media='all'`, `<noscript>`-фолбэк) — при недоступности шрифта страница рисуется сразу на `system-ui` (он и так был фолбэком по дизайн-системе), Golos Text подключается тихо, если/когда догрузится. Проверено Playwright: с полностью заблокированным fonts.googleapis.com страница отрисовывается за ~0.6с вместо зависания.
- серверный · pwa.js: сообщение «недоступно — откройте в Chrome или Safari» при клике на кнопку установки без нативного prompt было неточным (Яндекс.Браузер тоже умеет ставить PWA) — заменено на нейтральное.
- серверный · баг «правки не появляются на сайте»: `@fastify/static` отдавал html/js/css с `Cache-Control: max-age=3600` (час) — при активной разработке с несколькими деплоями в час браузер посетителя молча показывал версию часовой давности, не заходя на сервер вообще. `setHeaders` в опциях плагина не помог перебить это (сам `@fastify/static` расставляет `Cache-Control` уже ПОСЛЕ вызова `setHeaders`) — решение через глобальный хук `onSend` в `src/server.js`, выставляющий `Cache-Control: no-cache` по `content-type` ответа (html/js/css → всегда идти на сервер и проверяться по ETag, картинки/иконки — кэш как был). Владельцу для проверки: жёсткое обновление страницы (Ctrl/Cmd+Shift+R) или закрыть-открыть вкладку — дальше новые правки будут долетать сразу.

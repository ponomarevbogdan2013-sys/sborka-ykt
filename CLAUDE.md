# Дом Мастеров (бывш. СБОРКА) — маркетплейс мастеров (Якутск)

Контекст для Claude, работающего над этим проектом на сервере. Читай целиком перед первой правкой.

## Что это

Веб-платформа (сайт + PWA) «Дом Мастеров» (домен мастера14.рф; в WhatsApp/MAX-текстах — «Мастера14»; в коде и сервисах осталось имя `sborka`). Клиент считает стоимость в калькуляторе и оставляет заявку, мастера откликаются ценой, клиент выбирает по цене и рейтингу.

**Категории** (с 2026-10-29; таблица `service_categories`, коды = ключи `public/catalog.json`):

| Код | Название | Комиссия платформы |
|---|---|---|
| `furniture` | Сборка мебели | 20% (до 2026-10-30 — 30%) |
| `doors` | Установка дверей | 20% |
| `plumbing` | Сантехника (только установка и подключение купленного) | 20% |

- Партнёру — 5% от суммы во всех категориях (`partners.commission_pct`, не зависит от категории).
- Комиссия берётся из `service_categories.commission_pct` категории заказа в момент выбора мастера (`routes_client.js` → choose) и фиксируется в `orders.commission_rub`.
- Только плановые заказы, механика одна на все категории. Одна заявка = одна категория (`orders.category`, FK на `service_categories`).
- Мастер видит в ленте, получает пуш и WhatsApp/MAX «новая заявка» ТОЛЬКО по своим направлениям (`master_categories`) — условие одинаковое в 3 местах: `/api/master/feed`, `queueNewOrderPush` (server.js), `enqueueNewOrderMasters` (messenger.js). Отклик на заявку чужой категории — 403. Минимум одно направление у мастера (регистрация, активация, анкета).
- Клиент: переключатель `#catSeg` над калькулятором, `?c=doors` / `?c=plumbing` в ссылке (работает вместе с `?ref=`). Кросс-продажа: на экране заявки (сразу после отправки) для мебели с кухней — карточка «Заявка сантехнику →» (отдельная заявка, контакты и адрес подставляются).
- Новая категория = строка в `service_categories` (миграция) + блок в `catalog.json` + кнопка в `#catSeg` (`index.html`) + `CAT` в `src/admin_page.html`.

Полная концепция — `docs/concept.md`. Дорожная карта — `docs/roadmap.md`. Готовый кликабельный макет всех экранов — `reference/mockup.html` (это эталон дизайна и логики, открой в браузере).

## Стек (рекомендация — адаптируй под реальный сервер)

- **Фронт**: папка `public/` (`index.html` + `css/app.css` + `js/app.js`), все экраны свёрстаны. НЕ пересобирать и не заменять фреймворком. Правки — строго по дизайн-системе (см. «ГЛАВНОЕ ПРАВИЛО» выше), не «с нуля на глаз».
- **Бэк**: Node.js (Fastify/Express) или Cloudflare Workers — по тому, что стоит на сервере.
- **БД**: PostgreSQL (Neon или локальный на сервере).
- **Уведомления**: владельцу — Telegram (`src/events.js`/`notify.js`); мастерам — web-push. Клиенту «мастер откликнулся» — свои каналы с аккаунта номера, без агрегаторов: `src/messenger.js` (роутер WhatsApp → MAX → резерв владельцу в Telegram), сервисы `sborka-wa` (`src/wa_service.js`, Baileys, :3101) и `sborka-max` (`max_service/app.py`, PyMax, :3102) — только 127.0.0.1. Режим `MESSENGER_MODE` off/test/live, управление и тест — `/admin/messenger`. Мастеру можно отключить WhatsApp/MAX кнопкой во вкладке «Мастера» (`masters.messenger_off`; пуши и лента не зависят). Шлём умеренно (правила против бана — в шапке `messenger.js`), сессии — `.env`/БД/`max_service/data/`, в git не коммитить.
- **Вход**: клиент — без регистрации (заявка с именем + телефоном); мастер — простой логин (кабинет, отклики, рейтинг). Мастер попадает в кабинет двумя путями: персональный инвайт `/m?invite=<токен>` (одноразовый, `POST /api/admin/masters/invite`) или общая ссылка `/m?join=<MASTER_JOIN_CODE>` (код в `.env`; самостоятельная регистрация, `POST /api/master/register`; сменить код в `.env` + рестарт — старая ссылка умирает). SMS-верификацию НЕ вводим на старте.
- **Админка владельца**: `/admin` (Basic Auth из `.env`: `ADMIN_USER`/`ADMIN_PASS`) — вкладки: Дашборд (показатели, воронка, «требует внимания»), журнал событий, заказы с откликами, мастера (проверка/блокировка, приглашения: ссылка + QR), партнёры (переходы, клиенты, начислено/выплачено, запросы на вывод, запись выплат), лог уведомлений. Владельцу в Telegram уходят уведомления о каждом событии сделки (`src/events.js`). Новое событие в сделке = добавить `deal_events` + `ownerEvent(...)` в обработчике.

Первым делом уточни у Богдана фактические параметры сервера (ОС, что установлено, домен) и подстрой стек — не начинай ставить окружение вслепую.

## Ключевые продуктовые правила (не нарушать)

1. **Не чистый аукцион.** Клиент ставит бюджет-ориентир, калькулятор подсказывает вилку, мастера откликаются ценой + рейтингом. Клиент выбирает лучшего в бюджете, не самого дешёвого. Гонку на дно не строим.
2. **Чат и оплата — через платформу.** Иначе мастера уводят клиентов, и платформа умирает. На старте номера могут быть видны (живём на потоке), но архитектуру закладывать под маскировку контактов.
3. **Калькулятор поднимает чек** — допы встроены в расчёт, вилка «от–до», считает по внутреннему прайсу, наружу только вилка.
4. **Партнёрская атрибуция** — ссылки вида `?ref=uyut`, источник фиксируется за клиентом, магазин получает комиссию.

## Прайс калькулятора — `public/catalog.json` (единственный источник)

Все цены, подписи категорий и допы — в **`public/catalog.json`**: `{ furniture|doors|plumbing: {label, subtitle, listLabel, photoHint, whenLabel, emptyHint, title, items:[{id,nm,pr,unit}], addons:[{id,nm,pr,mult?,unit?,after?}]} }`. Таблицу цен здесь больше не дублируем — смотреть файл.
- Браузер берёт его `fetch('/catalog.json')` (`public/js/app.js`), бэк читает `fs.readFileSync` при старте (`src/pricing.js`). В `pricing.js` и `app.js` массивов цен НЕТ — только формула: низ = округл_100(сумма×mult), верх = округл_100(сумма×mult×1.2).
- Позиции/допы, которых нет в категории заказа, бэк отбрасывает. Доп с `unit` — поштучный (степпер), `after` — после какой позиции его показать (врезка в столешницу — под проектной кухней). `mult` — надбавка («Срочно» ×1.2, только у мебели).
- Цены показываются с префиксом «от», кроме «Срочно» (+20%). Вилка — сумма…сумма×1.2.
- `GET /api/pricing` отдаёт весь каталог как есть.

**Как менять прайс:** правка `public/catalog.json` → `systemctl restart sborka-web` (бэк читает файл только при старте; браузеры получают новый файл сразу — он отдаётся с `Cache-Control: no-cache`) → проверить `/api/pricing` и что в логе нет `вилка фронта … ≠ бэк`. Если меняется ФОРМАТ данных (новое поле) — ещё `app.js` (`recalc`/`getCalcState`), `pricing.js` (`calcEstimate`), `server.js` (`normalizeOrder`) и версия `?v=` у `js/app.js` в `index.html`.

## Структура фронта (public/)

- `index.html` — клиентский флоу: калькулятор → детали заявки → отклики мастеров → экран сделки со статус-трекером. Экраны переключаются по атрибуту `data-role` / `data-cview` (сейчас через демо-навигацию — при интеграции разведёшь по роутам/состоянию).
- `css/app.css` — вся дизайн-система: токены (обе темы), кнопки, карточки, чипы, трекер, калькулятор. Единственный источник стиля. Переиспользуй эти классы, новых стилей не плоди.
- `js/app.js` — калькулятор (прайс грузит из `catalog.json`, переключение категорий `setCategory`), навигация. `getCalcState()` → `{category, items, addons, total}`.
- `catalog.json` — прайс и подписи всех категорий (см. раздел выше).

Роли `master`, `partner`, `masterprofile`, `deal` в разметке — основа кабинетов мастера и партнёра; при интеграции вынеси в свои страницы/роуты, стиль бери из того же `app.css`.
